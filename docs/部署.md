# DoodleToday 部署

## 容器部署

服务器上从公开仓库拉取代码后，单独创建权限为 `600` 的 `.env`。该文件不提交到 GitHub，至少需要：

```dotenv
INVITE_CODE=replace-with-a-private-code
RENDER_TOKEN=replace-with-a-private-random-token
MODEL_BASE_URL=https://your-provider.example/v1
MODEL_API_KEY=replace-with-a-private-key
MODEL_ID=your-tool-capable-model
SECURE_COOKIE=true
```

启动：

```bash
docker compose up --build -d
docker compose ps
curl http://127.0.0.1:8101/api/health
```

服务仅发布 `8101`；Node 渲染器只监听容器内部回环地址。持久作品和 SQLite 数据保存在 `./data` volume。

## 域名与 HTTPS

在 DNS 服务商将完整域名（例如 `doodletoday.example.com`）的 A 记录指向服务器公网 IP，然后由 Nginx 或 Caddy 把 HTTPS 请求反向代理至 `127.0.0.1:8101`。域名必须是完整可解析的 FQDN；单独的 `doodletoday` 不能作为公网域名，也无法申请 TLS 证书。
