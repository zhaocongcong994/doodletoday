# 人格卡风格系统

## 第一阶段（已实施）

可信风格注册表位于项目根目录的 `style-registry.json`。它是前端选项、后端校验、模型风格上下文和 PNG 渲染的唯一 ID 来源。

当前预设：`magazine`、`labels`、`minimal`、`receipt`、`doodle`、`neon`、`soft-diary`、`archive`。

每条记录包含名称、说明和受控 `recipe`：

```json
{
  "base_layout": "receipt",
  "palette": ["#eee3cc", "#403a31", "#bd654c"],
  "decoration": ["perforation", "serial-number", "stamp"],
  "typography": "mono-editorial",
  "copy_tone": "怀旧、像一张被留存的凭据"
}
```

模型只能选择已注册 ID；服务端在渲染前会覆盖任何模型传入的配方，并把可信 `style_snapshot` 写进每个版本。旧版作品因此不受后续注册表修改影响。

## 第二阶段预留

`style_snapshot` 已在卡片版本 schema 中预留。新增“我的风格”时应创建独立、按用户归属的样式记录，再把其通过同样的 schema 校验并快照到版本；不得接收原始 CSS、SVG、脚本、外链资源或未授权字体。

推荐的后续接口：

- `GET/POST /api/styles`：列出与保存用户样式。
- `PUT/DELETE /api/styles/{id}`：修改或删除用户样式；删除不影响已保存版本。
- `POST /api/styles/preview`：仅接受受控配方，生成无模型调用的实际 PNG 预览。

可编辑的范围是注册表允许的布局、色板、装饰、字体角色和文案语气；每个组合都必须通过最长中文文案的 PNG 溢出测试。
